##  Streaming Platform SQL Project

---

## Overview

This project was completely generated by Claude Sonnet 5 in response to a prompt I gave it. Claude built everything from scratch, including:
- Schema: CREATE OR REPLACE TABLE statements for each table
- Sample Data: INSERT INTO statements populated with enough rows to make the queries return interesting results
- Phase 1-4 Questions: guided prompts written as SQL comments that ramp up in difficulty, from basic aggregations in Phase 1 to complex window frames and multi-step CTEs in Phase 4
- Hints: optional nudges commented out below each question without giving away the full answer

The dataset is intentionally small and synthetic, built specifically to make each phase's concepts produce clear and checkable results.

## Datasets and Data Model

| Tables | Description | Rows |
|---|---|---|
| users | platform accounts | 20 |
| content | movies and shows catalog | 25 |
| subscriptions | plan history per user | 30 |
| watch_history | individual viewing events | 120 |

- users -> subscriptions: one-to-many (each user can have multiple plan changes over time)
- users -> watch_history: one-to-many (each user has many viewing events)
- content -> watch_history: one-to-many (each title is watched many times, by many users)

- watch_history is the fact table connecting users and content. Most of the queries in Phases 2-4 revolve around aggregating or windowing over it.

---

## Phase Breakdown

- Phase 1 — Foundations: aggregations, `JOINs`, `GROUP BY`, `HAVING`, completion rates
- Phase 2 — Window basics: `DENSE_RANK`, `ROW_NUMBER`, `LAG`, `PARTITION BY`
- Phase 3 — Rolling windows: running totals, rolling averages, monthly active users, MoM change
- Phase 4 — Advanced topics: multi-step CTEs, cohort retention, churn detection, a custom popularity score, and a gaps-and-islands streak problem for Q4.5

## Skills Demonstrated

| Technique | Where it's used | What it shows |
|---|---|---|
| Window ranking (`DENSE_RANK`, `ROW_NUMBER`) | Q2.1, Q2.2 | Ranking and de-duplicating within groups |
| Rolling frames (`ROWS BETWEEN`) | Q3.1, Q3.2 | Running totals and rolling averages |
| `LAG` / month-over-month comparison | Q2.4, Q3.5 | Time-series deltas |
| Multi-step CTEs | Q4.1–Q4.5 | Breaking complex logic into readable stages |
| Plan changes | Q4.1 | `STRING_AGG` for building an ordered plan-progression string |
| Cohort retention analysis | Q4.2 | A common product-analytics pattern — grouping users by signup period and tracking return behavior over time |
| Custom scoring formulas | Q4.4 | Combining multiple metrics into a single weighted score |
| Gaps-and-islands streak detection | Q4.5 | Identifying consecutive-period patterns using row-number offset subtraction — a technique that comes up frequently in SQL interviews |

## Process Notes

While answering the questions in this project, I ran into some things worth noting:

- **Q3.4** (threshold) initially had an inverted comparison operator in my first answer. I was comparing the wrong side of the threshold multiplier, and it caused the query to flag 75 sessions instead of the correct 19. I caught this by checking specific rows against the expected logic by hand.

- **Q4.3** (Churn detection) returned 0 rows when running the query. Rather than assume that something was broken, I began isolating the filters and found 1 user who crossed the 90 day inactivity threshold. However, their subscription was still 'Active', so they didn't meet the defined churn definition. 0 rows was the correct answer.

## How To Run

For anyone interested in doing the project themselves to practice, I attached a blank copy of the file that Claude generated (streaming_platform_sql_project_blank.sql) as well as my solutions to those problems (streaming_platform_sql_project_solutions.sql).

Both files contain the instructions of how to start the project at the top. You have 3 different methods of doing so:

### Option A — DuckDB CLI:
- Install DuckDB: https://duckdb.org/docs/installation
- Open terminal and run: duckdb my_streaming.db
- At the DuckDB prompt: .read streaming_platform_sql_project_blank.sql (or paste sections manually)

### Option B — Python:
- pip install duckdb
- import duckdb
- con = duckdb.connect('my_streaming.db')
- con.execute(open('streaming_platform_sql_project_blank.sql').read())

### Option C — DBeaver (GUI):
- Download DBeaver and create a DuckDB connection
- Open this file and run sections as needed

I went with Option C for this project, but the other options should work as well.
